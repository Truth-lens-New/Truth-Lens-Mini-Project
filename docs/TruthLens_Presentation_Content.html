  • Checked API availability (Google Fact Check, GNews) and model support.

Slide 6: Research Design (Variables)

Independent Variables (What We Change)

  • Evidence source mix (fact-check API, news API, trust scoring).
  • Model/pipeline configuration and aggregation logic.
  • Input type and quality (claim text, URL extraction quality).

Dependent Variables (What We Measure)

  • Verdict quality/accuracy.
  • Precision/recall style performance on test claims.
  • System latency and user-perceived usefulness.

Extraneous Variables (Noise/Uncontrolled Factors)

  • API rate limits, outages, or network delays.
  • Ambiguous claims and rapidly changing real-world events.
  • Bias or inconsistency in external evidence sources.

Controls/Mitigation

  • Fallback logic, confidence blending, and source cross-validation.
  • Consistent test sets and repeated trial runs.

Slide 7: Data Collection Methods Used

Primary Data Collection

  • User-provided claims and URLs through the application.
  • User-uploaded media inputs (images and short videos) for forensic checks.
  • Live evidence from Google Fact Check API and GNews API.

Secondary Data Collection

  • Domain trust seed data.
  • Known misinformation references and curated datasets.
  • Deepfake image model weights and benchmark references for media analysis.
  • Technical documentation and prior studies for system design decisions.

Data Quality Steps

  • Normalization, deduplication, and relevance filtering.
  • Frame sampling and preprocessing checks for video reliability.
  • Source credibility weighting in verdict aggregation.

Slide 8: System Snapshot (What We Built)

  • Frontend: React + TypeScript (interactive verification UI).
  • Backend: FastAPI services for claim extraction, evidence retrieval, stance analysis, and aggregation.
  • Database: PostgreSQL for user/auth/history data.
  • Infrastructure: Docker Compose for reproducible local deployment.
  • Output: Structured verdict + confidence + evidence + explanation (when LLM key is configured).

Slide 9: Image and Video Detection in TruthLens

Image Detection

  • Deepfake classifier based on EfficientNet-B0 checks image authenticity.
  • Metadata/EXIF analysis looks for AI-generation or manipulation signals.
  • Grad-CAM heatmap highlights suspicious visual regions.

Video Detection

  • Uploaded videos are handled in the media pipeline with frame-level analysis flow.
  • Frame consistency indicators are used to flag possible manipulation patterns.
  • Results are presented with confidence, evidence indicators, and verdict summary.
Speaker Notes: Mention that image detection is currently deeper and more mature; video analysis uses frame-centric forensic signals and can be expanded in future work.

Slide 12: Abstract Template (For Your Report)

This project presents TruthLens, a multi-modal misinformation detection platform designed to support evidence-based claim verification. The study addresses the challenge of rapidly validating online information by combining fact-check evidence retrieval, source trust analysis, stance modeling, media forensics (image/video checks), and verdict aggregation in a single workflow. The research follows an applied and exploratory methodology, including problem analysis, architecture design, API-driven data collection, implementation, and iterative testing. The developed system demonstrates practical feasibility for real-time assistance in identifying potentially misleading content. Results indicate that hybrid evidence pipelines improve verification support quality while highlighting limitations related to API dependency, claim ambiguity, and evolving information contexts. The work contributes an implementable framework for misinformation analysis and provides a foundation for future enhancements in model robustness and multimodal verification.
